## 📊 What I Work On

My projects generally start with understanding the **business requirements, KPIs, reporting needs, and goals** defined by the client or business team.

Depending on the project and data volume, I use **SQL and Power BI together** to build efficient reporting solutions.

### 🔹 Data Extraction & SQL

When working with large datasets, I use **SQL** to retrieve and prepare only the data required for the reporting solution.

This helps reduce unnecessary data movement and improves the overall performance and maintainability of the Power BI model.

My SQL work includes:

* Complex queries and joins
* Views and stored procedures
* Data cleansing and transformation
* Duplicate handling
* Aggregations and summaries
* ETL/loading processes
* Performance-oriented data preparation

### 🔹 Power BI & Data Modeling

Once the required data is available in Power BI, I focus on building a structured and scalable **data model**.

My approach generally includes:

* Identifying the appropriate **Fact tables**
* Creating **Dimension tables**
* Establishing relationships between tables
* Building Date/Calendar dimensions
* Creating calculated columns and measures where required
* Designing a model that supports flexible analysis
* Following **Star Schema** principles wherever appropriate

For example, when a fact table contains transaction dates, I create a dedicated **Date Dimension** that can provide additional information such as Year, Month, Quarter, Week, and other calendar attributes required for analysis.

## 🧮 DAX & Business Logic

A major part of my Power BI work involves converting business requirements into analytical logic using **DAX**.

I work with concepts such as:

* `CALCULATE`
* Filter Context
* Row Context
* `FILTER`
* `SUMX` / `COUNTX` and iterator functions
* Time Intelligence
* MTD / LMTD / YTD
* MoM / YoY analysis
* Retention & conversion analysis
* Customer / Vehicle lifecycle analysis
* Dynamic KPIs
* Business-specific measures and segmentation

My focus is not only on creating a measure that returns the correct number, but also on understanding **why the DAX works within a particular filter context**.

## 📈 Dashboard & Reporting

The final objective is to convert the prepared data and business logic into dashboards that are:

* Easy to understand
* Interactive
* Performance-oriented
* Business-focused
* Scalable
* Useful for decision-making

I pay particular attention to the **data model, amount of data being loaded, relationships, DAX performance, and report design**, because these factors directly affect the usability and performance of a Power BI solution.

A good visualization starts with a good data foundation.
